# Benchmark Reference — Workflow / Durable Execution Engines

Governs: [`docs/004-TECHNOLOGY-SELECTION-RECORD.md`](../docs/004-TECHNOLOGY-SELECTION-RECORD.md) §3.9

**Note on methodology:** directional comparison from vendor documentation and public case studies, not AOS-measured.

| Dimension                                   | Temporal                                                                         | Inngest                                                                        | Trigger.dev                                                   | Internal (build from scratch)                                                   |
| ------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Durability guarantee model                  | Deterministic replay of full event history — strongest guarantee category        | Managed, durable step functions — strong guarantee, different underlying model | Managed, durable step functions — similar category to Inngest | Depends entirely on implementation quality — unproven by definition             |
| Operational setup cost                      | Higher (own server + persistence store to run, or managed Temporal Cloud)        | Lower (largely managed)                                                        | Lower (largely managed)                                       | Highest (must build durability, retries, compensation, observability from zero) |
| Time-to-first-workflow-in-production        | Slower initial ramp (learning curve for deterministic-workflow-code constraints) | Fast                                                                           | Fast                                                          | Slowest                                                                         |
| Proven multi-tenant SaaS scale track record | Strong (multiple large-scale public case studies)                                | Growing, newer product                                                         | Growing, newer product                                        | None (would be AOS's own first proof)                                           |
| Compensation/saga pattern support           | Native, well-documented                                                          | Supported                                                                      | Supported                                                     | Must be designed and built                                                      |

**Relevance to AOS (§3.9):** the decision explicitly separates "what's fastest to get an MVP live" (Inngest/Trigger.dev) from "what has the strongest durability guarantee at the platform's eventual thousands-of-tenant, multi-week-nurturing-sequence scale" (Temporal) — both are legitimate answers depending on team stage, which is why the TSR names Temporal as the target architecture while explicitly permitting an Inngest/Trigger.dev MVP path with a pre-planned migration, rather than forcing a single answer that ignores the real trade-off between initial velocity and long-term durability guarantees.
