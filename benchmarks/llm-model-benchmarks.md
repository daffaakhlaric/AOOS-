# Benchmark Reference — LLM Model Tiers

Governs: [`docs/004-TECHNOLOGY-SELECTION-RECORD.md`](../docs/004-TECHNOLOGY-SELECTION-RECORD.md) §4 (AI Model Strategy)

**Note on methodology:** relative positioning only, based on published provider documentation and commonly reported industry benchmark categories (reasoning/agentic tool-use benchmarks, context window specs, published pricing tiers) as of this writing. Absolute pricing and benchmark scores change frequently and are intentionally not hard-coded here — the Model Registry (Registry Contract) is the live source of truth for actual routing configuration; this file documents the _reasoning_, not a snapshot to be trusted as current pricing.

| Dimension                                                                    | Top reasoning tier (e.g., Claude Opus-class)                       | Mid/balanced tier (e.g., Claude Sonnet-class, GPT mid-tier) | Fast/cheap tier (e.g., Claude Haiku-class, GPT-mini-class)                   | Long-context/grounding tier (e.g., Gemini-class)  |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------- |
| Relative cost per token                                                      | Highest                                                            | Medium                                                      | Lowest                                                                       | Medium (varies by context length used)            |
| Relative latency (time-to-first-token, typical)                              | Slowest                                                            | Medium                                                      | Fastest                                                                      | Medium                                            |
| Agentic tool-use reliability (multi-step plans, structured output adherence) | Highest                                                            | High                                                        | Medium                                                                       | Medium-High                                       |
| Context window                                                               | Large                                                              | Large                                                       | Moderate-Large                                                               | Very Large                                        |
| Best-fit AOS use case                                                        | CEO AI/COO AI strategic planning, high-`security_level` Reflection | Marketing AI, Content Generation                            | Sales AI Lead Scoring (high frequency), Conversational AI (latency-critical) | Research Agent, long-document Knowledge synthesis |

**Relevance to AOS (§4):** the routing table in the master TSR document is deliberately expressed as _tiers_, not fixed vendor/model names, because this table's relative positions are stable even as the specific model filling each tier changes over time (new model releases, price changes) — this is the entire justification for the Model Router/Model Contract abstraction (doc 003.5 §14, ADR-008 in doc 002): the tier-to-Agent-category mapping is durable; the tier-to-specific-model mapping is a Model Registry configuration value, updated independently.
