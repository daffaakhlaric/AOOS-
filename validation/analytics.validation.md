# Analytics Contract — Validation Rules (VAL-169 – VAL-180)

Governs: [`analytics.contract.md`](../contracts/analytics.contract.md) · Schemas: [`analytics.schema.yaml`](../schemas/analytics.schema.yaml), [`analytics.schema.json`](../schemas/analytics.schema.json)

| ID      | Rule                                                                                                                                                                                              | Severity | Governing Source               |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ------------------------------ |
| VAL-169 | `metric` MUST match `^[a-z][a-z0-9_]*$` and MUST be unique across all `active` Metric definitions.                                                                                                | Blocking | Schema constraint              |
| VAL-170 | `aggregation` MUST be one of `sum`, `avg`, `count`, `p50`, `p95`, `p99`, `ratio`.                                                                                                                 | Blocking | Constitution §25.1             |
| VAL-171 | `dimension` MUST include `tenant_id`.                                                                                                                                                             | Blocking | DDD §25 Tenant Isolation       |
| VAL-172 | Every entry in `source_events` MUST reference a Domain Event name cataloged in DDD §12, ingested only via the Event Bus.                                                                          | Blocking | Constitution RULE-023          |
| VAL-173 | If `metric` matches a KPI name in the DDD §28 catalog, `definition` MUST be textually identical to the catalog's Definition column.                                                               | Blocking | DDD §28                        |
| VAL-174 | `retention.hot_days` MUST be ≤ `retention.cold_days`.                                                                                                                                             | Blocking | Analytics Contract §4          |
| VAL-175 | `sampling.rate`, when present, MUST be between 0 and 1 inclusive.                                                                                                                                 | Blocking | Schema constraint              |
| VAL-176 | If `export.destinations` includes `third_party_bi`, `export.tenant_isolation_required` MUST be `true`.                                                                                            | Blocking | Constitution §20.1             |
| VAL-177 | `state = active` REQUIRES `rollup_schedule` and `freshness_sla` to both be non-null.                                                                                                              | Blocking | Analytics Contract §4          |
| VAL-178 | `domain` MUST be one of the DDD §28 catalog's Domain values (`dealer`, `sales`, `campaign`, `ads`, `content`, `ai_agent`, `workflow`).                                                            | Blocking | DDD §28                        |
| VAL-179 | A Metric's `definition` or `aggregation` MUST NOT change in place once `state = active`; redefinition MUST publish a new Metric and deprecate the prior one.                                      | Blocking | Constitution RULE-011          |
| VAL-180 | A Metric with `freshness_sla` exceeding 24 hours on a `domain = ai_agent` or `domain = sales` metric SHOULD be flagged for review — near-real-time domains typically require sub-daily freshness. | Warning  | Architecture §22 Best Practice |
