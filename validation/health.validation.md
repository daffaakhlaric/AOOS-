# Health Contract — Validation Rules (VAL-193 – VAL-204)

Governs: [`health.contract.md`](../contracts/health.contract.md) · Schemas: [`health.schema.yaml`](../schemas/health.schema.yaml), [`health.schema.json`](../schemas/health.schema.json)

| ID      | Rule                                                                                                                                                                                                                                                      | Severity | Governing Source                       |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | -------------------------------------- |
| VAL-193 | `state` MUST be exactly one of `healthy`, `degraded`, `unhealthy`, `unknown`.                                                                                                                                                                             | Blocking | Schema constraint                      |
| VAL-194 | `id`, `component_ref`, `heartbeat`, `availability`, `latency`, `error_rate`, `recovery`, `dependency_check`, `readiness_gate`, `state`, `last_evaluated` MUST all be present.                                                                             | Blocking | Schema constraint                      |
| VAL-195 | `heartbeat.interval` MUST be strictly less than `heartbeat.timeout`.                                                                                                                                                                                      | Blocking | Health Contract §4                     |
| VAL-196 | `availability.slo_target` MUST be greater than 0 and at most 100.                                                                                                                                                                                         | Blocking | Constitution §25.3                     |
| VAL-197 | `latency.p50_ms` ≤ `latency.p95_ms` ≤ `latency.p99_ms`.                                                                                                                                                                                                   | Blocking | Constitution §26.1                     |
| VAL-198 | Every entry in `dependency_check` MUST include a non-empty `health_ref` resolving to another Health Contract instance.                                                                                                                                    | Blocking | Health Contract §4                     |
| VAL-199 | If `recovery.mode = automatic` and `component_ref` denotes a Tool-backed component, `recovery.circuit_breaker_ref` MUST be present.                                                                                                                       | Blocking | Constitution §18.6                     |
| VAL-200 | If `readiness_gate = true`, `latency.budget_ms` MUST be non-null.                                                                                                                                                                                         | Blocking | Health Contract §4                     |
| VAL-201 | `error_rate.threshold_percent` MUST be between 0 and 100 inclusive.                                                                                                                                                                                       | Blocking | Schema constraint                      |
| VAL-202 | `state = unhealthy` persisting beyond `heartbeat.timeout` × 3 MUST be accompanied by a `severity = CRITICAL` Logging Contract record.                                                                                                                     | Blocking | Health Contract §5, Constitution §17.3 |
| VAL-203 | `recovery.mode = manual` SHOULD carry a non-null `manual_runbook_ref`; absence is flagged for on-call readiness review.                                                                                                                                   | Warning  | Constitution §25.4                     |
| VAL-204 | `dependency_check` SHOULD enumerate every downstream dependency actually invoked by `component_ref` (e.g., every Tool in an Agent's `toolset`); an incomplete dependency graph is a Warning, verified via cross-reference audit rather than schema alone. | Warning  | Architecture §23                       |
