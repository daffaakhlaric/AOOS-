# Workflow Contract — Validation Rules (VAL-025 – VAL-036)

Governs: [`workflow.contract.md`](../contracts/workflow.contract.md) · Schemas: [`workflow.schema.yaml`](../schemas/workflow.schema.yaml), [`workflow.schema.json`](../schemas/workflow.schema.json)

| ID      | Rule                                                                                                                                                                                                          | Severity | Governing Source                       |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | -------------------------------------- |
| VAL-025 | `workflow_id` MUST match `^workflow\.[a-z][a-z0-9_]*$` and MUST NOT change across versions.                                                                                                                   | Blocking | Workflow Contract §1                   |
| VAL-026 | Every `edges[].from` and `edges[].to` MUST reference an existing `node_id` in `nodes`.                                                                                                                        | Blocking | Workflow Contract §4                   |
| VAL-027 | Every node invoking a Tool with `side_effect_class` of `reversible-write` or `irreversible-write` MUST have a non-null `compensation` reference, either on the node or in the top-level `compensation` array. | Blocking | Constitution RULE-028                  |
| VAL-028 | `nodes` MUST declare `timeout` and `retry_policy` per step.                                                                                                                                                   | Blocking | Constitution §10.2                     |
| VAL-029 | Side-effecting nodes MUST use an idempotency key on resume/retry — no step already succeeded may re-execute after a crash.                                                                                    | Blocking | Constitution §10.4, RULE-029, RULE-030 |
| VAL-030 | `state_machine.states` MUST equal exactly `{Created, Running, Paused, Failed, Completed, Compensated}` whenever `rollback.supported = true`.                                                                  | Blocking | DDD §17.3, Workflow Contract §4        |
| VAL-031 | `state_machine.transitions` MUST mirror the canonical Workflow state machine (DDD §17.3) — no undocumented states or transitions.                                                                             | Blocking | DDD §17.3                              |
| VAL-032 | `parallel_execution.enabled = true` REQUIRES `parallel_execution.join_strategy` to be non-null.                                                                                                               | Blocking | Workflow Contract §4                   |
| VAL-033 | `priority` MUST be an integer between 1 and 10 inclusive.                                                                                                                                                     | Blocking | Schema constraint                      |
| VAL-034 | `timeout` and `cost_budget` MUST both be present and non-null before `status` may be `active`.                                                                                                                | Blocking | Constitution §10.6                     |
| VAL-035 | `human_checkpoints[].node_id` MUST reference an existing `node_id` in `nodes`.                                                                                                                                | Blocking | Constitution §10.7                     |
| VAL-036 | `version` MUST follow strict SemVer and MUST be strictly greater than the previous published version for the same `workflow_id`.                                                                              | Blocking | Constitution RULE-070                  |
