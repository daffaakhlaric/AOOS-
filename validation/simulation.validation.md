# Simulation Contract — Validation Rules (VAL-205 – VAL-216)

Governs: [`simulation.contract.md`](../contracts/simulation.contract.md) · Schemas: [`simulation.schema.yaml`](../schemas/simulation.schema.yaml), [`simulation.schema.json`](../schemas/simulation.schema.json)

| ID      | Rule                                                                                                                                                                                                         | Severity | Governing Source                                   |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- | -------------------------------------------------- |
| VAL-205 | `seed` MUST be a non-negative integer.                                                                                                                                                                       | Blocking | Simulation Contract §4                             |
| VAL-206 | Identical (`seed`, `scenario.scenario_id`) pairs MUST deterministically reproduce identical synthetic stimuli across runs.                                                                                   | Blocking | Architecture §30                                   |
| VAL-207 | `dummy_dealer.tenant_id` MUST be prefixed `sim_` and MUST NOT match any real Tenant Aggregate ID.                                                                                                            | Blocking | Simulation Contract §4                             |
| VAL-208 | Every `dummy_crm`/`dummy_whatsapp`/`dummy_meta`/`dummy_google_ads`/`dummy_tiktok_ads` `adapter_mode` MUST equal `sandboxed`; any other value is a publish-blocking safety violation.                         | Blocking | Architecture §30 Dependencies                      |
| VAL-209 | `sandbox_isolation.network_egress_denied` MUST be `true` for the entire duration of `state = running`.                                                                                                       | Blocking | Simulation Contract §4 (critical safety invariant) |
| VAL-210 | `scenario.expected_outcome` MUST be non-null before `state` may transition to `running`.                                                                                                                     | Blocking | Simulation Contract §4                             |
| VAL-211 | If `replay.replayable = true`, `replay.deterministic_hash` MUST be present.                                                                                                                                  | Blocking | Simulation Contract §4                             |
| VAL-212 | `candidate_ref` MUST resolve to a Registry entry whose `state = draft` for first-time promotion runs.                                                                                                        | Blocking | Simulation Contract §4                             |
| VAL-213 | `state = completed` REQUIRES `outcome_scorer` to be present with `pass` explicitly `true` or `false`.                                                                                                        | Blocking | Simulation Contract §4                             |
| VAL-214 | `dummy_budget` MUST NOT be bound to any real payment/spend Adapter; the sandbox's adapter binding table MUST exclude real Money-movement Adapters entirely.                                                  | Blocking | Simulation Contract §4                             |
| VAL-215 | An Agent/Workflow/Model/Prompt Registry entry MUST NOT transition `draft` → `active` without at least one `completed` Simulation run with `outcome_scorer.pass = true` against a non-empty Scenario Library. | Blocking | Architecture §30 Best Practice                     |
| VAL-216 | `outcome_scorer.guardrail_trigger_rate` above the tenant's configured Guardrail tolerance SHOULD be flagged for manual review even when `pass = true` on accuracy/cost/latency alone.                        | Warning  | Architecture §30 Output                            |
