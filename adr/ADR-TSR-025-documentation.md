# ADR-TSR-025 — Documentation: Docusaurus (Internal) + Mintlify (External)

**Status:** Accepted

**Context:** Constitution §22 (Documentation Standards) requires the living Engineering Handbook document series (docs 001 through 004 and beyond) to remain versioned, reviewable, and self-hosted, while the Contract Specification (doc 003.5) produces machine-readable JSON Schemas for every Agent/Tool/Workflow/Event contract that must eventually be published as browsable, developer-facing API/SDK reference documentation once the Core Runtime and SDK exist. These are two audiences with different needs: internal engineers reading a constitutional document set, and external/partner developers integrating against AOS's Contract-derived API surface. Candidates evaluated: Docusaurus, MkDocs, Mintlify.

**Decision:** Adopt a **dual-tool recommendation**: **Docusaurus** for the internal Engineering Handbook (this document series) — React-based (consistent with the TypeScript-first stack, ADR-TSR-001/003), fully self-hostable, highly customizable, with strong versioning support suited to a living, amendable constitutional document set. **Mintlify** for external-facing Developer/API/SDK documentation once it exists — modern developer experience, strong native OpenAPI/JSON-Schema integration well-suited to publishing the Contract Specification's schemas (doc 003.5) as browsable, interactive API reference. **MkDocs** is not adopted for either audience — Docusaurus covers the same ground with a more actively maintained plugin ecosystem for a TypeScript-first team, though MkDocs remains a fine choice for teams preferring Python-based documentation tooling and is not disqualified for a future Python-scoped internal tool (ADR-TSR-001's Python-for-AI-tooling scope) if a need arises there specifically.

**Consequences:** The platform maintains two documentation toolchains rather than one, reflecting that "internal engineering handbook" and "external developer API reference" are genuinely different products with different audiences, update cadences, and ownership — not an arbitrary tooling split. Docusaurus content (docs 001–004+) stays self-hosted and fully under AOS's control; Mintlify's external-facing docs may depend on Mintlify's hosting platform, a vendor dependency scoped deliberately narrowly to public-facing reference material rather than any internal or sensitive content.

**Alternatives Considered:**

- **MkDocs (for either audience)** — not rejected outright, but not adopted as primary for a TypeScript-first team; remains a fine fallback for a Python-tooling-adjacent internal need.
- **A single unified tool for both audiences** — considered and rejected; the internal Handbook's self-hosting/full-control requirement and the external API reference's interactive-schema-browsing requirement are different enough that no single evaluated tool served both without a meaningful compromise on one side.
