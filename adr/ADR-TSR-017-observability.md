# ADR-TSR-017 — Observability: OpenTelemetry + Grafana/Prometheus/Loki/Tempo ("LGTM")

**Status:** Accepted

**Context:** AOS requires a tracing/metrics/logging instrumentation stack satisfying Constitution §17 (traceable AI decisions, RULE-047) and §25 (real-time per-tenant observability), and Architecture §23 Monitoring Architecture and §24 Logging Architecture, which mandate a shared Observability SDK across every service, tenant-tagged signals (`tenant_id`, `trace_id`, RULE-045), and per-tier SLO/burn-rate alerting. A metered SaaS observability product (Datadog, New Relic — evaluated separately at §3.23 Monitoring) risks per-GB-ingested/per-host cost growing faster than dealer count as the platform's own service/Agent footprint scales, in tension with Constitution §33 Cost Optimization.

**Decision:** Adopt **OpenTelemetry** as the mandatory instrumentation standard for every service, Agent, Tool, and Workflow — all traces, metrics, and logs are emitted via OTel SDKs and routed through OTel Collectors, per Architecture §38's tracing recommendation. Adopt a self-hostable **Grafana + Prometheus + Loki + Tempo ("LGTM") stack** as the default backend: Prometheus for metrics, Loki for logs, Tempo for traces, Grafana as the unified dashboard/query layer with native trace-log-metric correlation. Do not separately adopt Jaeger — Tempo's native Grafana integration is the better-integrated choice for AOS's single-pane operational model.

**Consequences:** AOS operates four self-hosted components (plus the OTel Collector fleet) rather than consuming a single managed SaaS agent, an operational cost accepted for infrastructure-bound (not per-signal-metered) pricing at multi-tenant scale (`cost-analysis/cost-model-100-1000-10000-dealers.md` §9) and named explicitly as a re-evaluation risk (`risk/risk-register.md` RISK-005). Because instrumentation is OTel-standard rather than backend-specific, the platform retains the ability to redirect signals to Datadog, New Relic, or Grafana Cloud purely via Collector export configuration if self-hosting ops toil ever exceeds its savings, without re-instrumenting any service code (`migration/migration-and-upgrade-strategy.md` §2). Loki/Tempo/Grafana's AGPL-3.0 licensing must be tracked if these tools are ever exposed directly to dealer tenants as a product feature rather than used as internal AOS tooling.

**Alternatives Considered:**

- **Jaeger** — mature, CNCF-graduated, Apache-2.0-licensed standalone tracing backend; not adopted because it does not extend to metrics/logs and lacks Tempo's native single-pane Grafana correlation, which is materially valuable for incident investigation across trace/log/metric signals together.
- **A metered SaaS observability product (Datadog/New Relic)** — superior out-of-box UX and APM auto-instrumentation polish, acknowledged directly; not adopted as the default because per-host/per-GB-ingested pricing scales unfavorably against AOS's multi-tenant, many-services cost model at 1,000+ and 10,000-dealer scale (fully treated at §3.23 Monitoring, this ADR's sibling decision).
