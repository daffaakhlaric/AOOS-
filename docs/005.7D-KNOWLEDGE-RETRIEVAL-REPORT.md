# ENGINEERING TASK 005.7D — Enterprise Knowledge Retrieval — Closing Report

Package: `packages/knowledge-retrieval` (`@aos/knowledge-retrieval`)
Source prompt archived at: `docs/PROMPT-005.7D-KNOWLEDGE-RETRIEVAL.md`

Scope actually implemented: the vendor-neutral Enterprise Retrieval Orchestrator every
future Agent uses to retrieve enterprise knowledge — a 10-state Retrieval Lifecycle, a
9-stage Pipeline (Validation → Permission → Policy → Namespace → Search Strategy →
Ranking → Filtering → Result Builder → Metrics), a token/id-addressed Registry (7
buckets), a Manager orchestrating Registry + Session + Statistics, dispatch-only Search
Strategy and Ranking Engine classes, a Permission Resolver and a Policy Resolver (the
latter reusing `@aos/knowledge-engine`'s real `KnowledgePolicyEngine`), a structural
Filter, a 6-sub-factory Factory, an 8-event `KnowledgeRetrievalEvents` publisher,
Metrics/Health/Monitoring, 12 interface-only extension points, and the
`KnowledgeRetrieval`/`KnowledgeRetriever` public façade (plus its
`KnowledgeRetrievalSystem` Kernel Module wrapper). **No embedding generation, no vector
database, no LLM, no AI reasoning, no prompt engineering, no memory, no synchronization,
no chunking, and no knowledge indexing** was implemented, imported, or stubbed anywhere in
this package — it only orchestrates the retrieval request lifecycle over
`@aos/knowledge-engine`/`@aos/knowledge-indexing`, dispatching to caller-supplied Search
Strategy/Ranking providers.

## 2. Retrieval Flow

A caller obtains a `KnowledgeRetrieval` instance (constructed from a real
`KnowledgeEngine` + `KnowledgeIndexing` pair), registers at least one
`IKnowledgeSearchStrategy` for the Search Modes it wants to serve, then calls
`retrieval.search(query, context, rankingStrategy?)`:

1. `KnowledgeRetriever.retrieve()` records `recordQueryStarted()`, creates a
   `KnowledgeRetrievalExecution` in the `CREATED` state, registers it in
   `KnowledgeRetrievalManager`, and publishes `SEARCH_STARTED`.
2. It transitions the Execution to `VALIDATING` and calls
   `KnowledgeSearchPipeline.run()` — one atomic call covering all 9 Pipeline stages.
3. On success, it rapidly transitions `RESOLVING` → `SEARCHING` → `RANKING` →
   `FILTERING` → `COMPLETED` (5 history entries recording that those stages occurred
   inside the single Pipeline call), stamps `results`/`resultCount`/`completedAt`, records
   `recordQueryCompleted()`, and publishes `SEARCH_RANKED`, `SEARCH_FILTERED`, and
   `SEARCH_COMPLETED`.
4. On failure, it transitions straight to `FAILED` with the error's message as the
   transition reason, records `recordQueryFailed()`, publishes `SEARCH_FAILED`, and
   rethrows.

`retrieval.cancel(token)` transitions an in-flight Execution to `CANCELLED` and publishes
`SEARCH_CANCELLED` — legal only from a non-terminal state, since all 4 "settled" states
(`COMPLETED`/`FAILED`/`CANCELLED`/`EXPIRED`) have zero outgoing transitions.

## 3. Domain Model

- **`KnowledgeRetrievalState`** (10 values): Created, Validating, Resolving, Searching,
  Ranking, Filtering, Completed, Failed, Cancelled, Expired — the authoritative
  `KNOWLEDGE_RETRIEVAL_STATE_TRANSITIONS` table lives in `domain/knowledge-retrieval-state.ts`;
  `state-machine/knowledge-retrieval-state-machine.ts` is the only code allowed to consult it.
- **`KnowledgeQueryType`** (13 values): Support, Question, Keyword, Metadata,
  Relationship, Namespace, Category, Tag, Hybrid, Template, Policy, Version, Collection.
- **`KnowledgeSearchMode`** (19 values): Keyword, Metadata, Relationship, Namespace,
  Category, Tags, Template, Hybrid, Semantic Reference, Exact Match, Prefix, Wildcard,
  Fuzzy, Version, Policy, Permission, Collection, Workspace, Tenant.
- **`KnowledgeRankingStrategy`** (7 values): BM25, Hybrid, Semantic, Cross Encoder,
  Vector Ranking, Rule Based, LLM Ranking — a tagging enum, not 7 separate interfaces
  (see §5).
- **`KnowledgeQuery`** (Zod schema): id, type, text?, keywords (default []), searchModes
  (min 1), filters, limit (default 20), offset (default 0), createdAt.
- **`KnowledgeFilterSet`** (Zod schema, 15 fields per the prompt's exact list):
  permission, policy, workspaceId, departmentId, tenantId, classification, language,
  region, categoryId, tags, version, templateId, source, assetType, lifecycleState.
  Permission/Policy are declared for schema completeness but never applied by
  `KnowledgeFilter` itself (see §8).
- **`KnowledgeResult`** (plain TS interface, not Zod — mirrors
  `@aos/knowledge-runtime`'s `KnowledgeRuntimeExecution` precedent for composite
  read-model types embedding values sourced from other packages): assetId, version,
  relationships (`KnowledgeRelationship[]` from `@aos/knowledge-engine`), score,
  confidence, matchedFields, matchedKeywords, matchedMetadata, matchedTags,
  matchedCategories, chunkRefs/embeddingRefs (`KnowledgeChunkReference[]`/
  `KnowledgeEmbeddingReference[]` from `@aos/knowledge-indexing`), namespace, policy?,
  permission?, source, searchMode, executionTimeMs.

## 5. Search Strategy & Extension Points

Three distinct, non-overlapping layers resolve the source prompt's apparent "12 Extension
Points vs 8 Search Strategy interfaces vs 7 Ranking interfaces" redundancy:

- **`contracts/`** — the 12 literal named Extension Point interfaces the prompt requires
  verbatim (true external integration points): `IKnowledgeKeywordSearchProvider`,
  `IKnowledgeMetadataSearchProvider`, `IKnowledgeRelationshipSearchProvider`,
  `IKnowledgeNamespaceSearchProvider`, `IKnowledgeHybridSearchProvider`,
  `IKnowledgeSemanticSearchProvider`, `IKnowledgeVectorSearchProvider`,
  `IKnowledgeRankingProvider`, `IKnowledgeCacheProvider`, `IKnowledgeResultPostProcessor`,
  `IKnowledgeSearchObserver`, `IKnowledgeSearchHook`. Six of the twelve are declared as
  `export type IXxx = IKnowledgeSearchProvider;` type aliases rather than empty interface
  extensions, avoiding `@typescript-eslint/no-empty-interface`.
- **`strategy/`** — 8 internal Strategy-pattern interfaces representing "how a Search
  Mode is executed" inside the Pipeline (`IKeywordSearchStrategy`,
  `IMetadataSearchStrategy`, `IRelationshipSearchStrategy`, `INamespaceSearchStrategy`,
  `IPolicySearchStrategy`, `IPermissionSearchStrategy`, `IHybridSearchStrategy`,
  `ISemanticSearchStrategy`), each a type alias of the shared `IKnowledgeSearchStrategy`
  base.
- **`KnowledgeRankingStrategy`** — a 7-value enum (not 7 separate interfaces) tagging
  which single registered `IKnowledgeRankingProvider` a caller wants, since the Extension
  Points list only names one Ranking Provider contract.

`KnowledgeSearchStrategy` (the Public API dispatcher class) owns no search algorithm
itself — `register()`/`execute()`/`isSupported()` only, throwing
`SearchStrategyNotFoundException` when nothing is registered for a requested Search Mode.

## 6. Pipeline

9 stages, in fixed order, run inside one atomic `KnowledgeSearchPipeline.run()` call:

1. **Validation** — `KnowledgeRetrievalValidator` (5 stages, see §9); throws
   `RetrievalValidationException` on any issue.
2. **Permission** (query-level gate) — optional `IQueryPermissionChecker`, permissive by
   default; throws `RetrievalPermissionDeniedException` when it rejects.
3. **Policy** (query-level gate) — optional `IQueryPolicyChecker`, permissive by default;
   throws `RetrievalPolicyViolationException` when it rejects.
4. **Namespace** — annotates `context.variables.namespaceScope` with the resolved
   `{ tenantId, workspaceId }` scope Search Strategies read.
5. **Search Strategy** — dispatches to the registered provider for every
   `query.searchModes` entry in parallel (`Promise.all`), flattening the results;
   records `recordSearchMode()` per mode.
6. **Ranking** — `KnowledgeRankingEngine.rank()`; timed via `recordRankingTime()`.
7. **Filtering** — `KnowledgeFilter.apply()` (structural fields) →
   `KnowledgePolicyResolver.resolve()` → `KnowledgePermissionResolver.resolve()`, in that
   order; timed via `recordFilterTime()`; records `recordPermissionReject()`/
   `recordPolicyReject()`.
8. **Result Builder** — applies `query.offset`/`query.limit` paging to the final allowed
   list.
9. **Metrics** — `recordTenantUsage()`, and `recordWorkspaceUsage()` when
   `context.workspaceId` is set.

The early Permission/Policy stages (positioned before Search Strategy, per the prompt's
own diagram) are a coarse-grained "may this Context run this Query at all" gate — distinct
from the real per-Result enforcement inside Filtering. "Permission filtering happens
BEFORE results are returned. Never expose unauthorized knowledge." is satisfied by the
Filtering stage, which runs before `KnowledgeRetriever` ever stamps `execution.results`.

## 7. Registry

One generic `KnowledgeRetrievalRegistry` class covering all 7 buckets the source prompt
requires: Search Strategy, Ranking Strategy, Filter, Policy, Permission Provider, Result
Builder, Search Provider — `register()`/`replace()`/`get()`/`require()`/`remove()`/
`list()`/`count()`, throwing `DuplicateRetrievalEntryException`/`RetrievalNotFoundException`
as appropriate. `KnowledgeRetrievalStatistics` deliberately does **not** use the Registry
— the source prompt's own 7-item Registry list omits "Statistics" — so it owns its own
private `Map<KnowledgeSearchMode, KnowledgeRetrievalStatisticsSnapshot>`, mirroring
`@aos/knowledge-engine`'s `KnowledgePermissionEngine` making the identical judgment call
for the identical reason.

## 8. Ranking Engine

"No algorithms. Only contracts." `KnowledgeRankingEngine` owns no ranking logic itself.
`register(strategy, provider)` stores an `IKnowledgeRankingProvider` keyed by
`KnowledgeRankingStrategy`. `rank(results, query, context, strategy?)`:

- Returns `results` unchanged, unmodified, when no `strategy` is requested — a documented
  no-op, never a silent algorithm.
- Dispatches to the registered provider when a specific `strategy` is requested and found.
- Throws `RankingNotSupportedException` when a specific `strategy` is requested and
  nothing is registered for it.

## 9. Permission Resolution

`KnowledgePermissionResolver.resolve(results, context)` filters `KnowledgeResult[]`
through an optional injected `IResultPermissionChecker.check(result, context)`, permissive
by default when unconfigured (`{ allowed: results, rejectedCount: 0 }`) — the same
"permissive-by-default checker delegation" pattern already used by
`@aos/workflow-runtime`/`@aos/knowledge-runtime`'s `PermissionMiddleware` and
`@aos/knowledge-indexing`'s `IKnowledgeIndexChecker`. Real `@aos/knowledge-engine`
`KnowledgePermissionEngine` reuse was ruled out — its `check()` requires a full
`KnowledgeContext` whose `token` field is typed `ExecutionToken` from
`@aos/workflow-execution`, which is not in this package's allowed Dependency Rules list.

## 10. Policy Resolution

`KnowledgePolicyResolver.resolve(results)` **does** reuse the real
`@aos/knowledge-engine` `KnowledgePolicyEngine` directly — `evaluate(asset)` needs no
`ExecutionToken`/`KnowledgeContext`, so the dependency-boundary concern that ruled out
direct Permission Engine reuse does not apply here. It filters out any Result whose
resolved `KnowledgeAsset` has one or more Policy violations; a Result whose Asset can no
longer be resolved (an orphaned Index Entry) passes through — there is nothing to
evaluate a Policy against. `KnowledgePolicyEngine.evaluate()` only understands
Retention/Classification/Compliance/Review rule fields (a documented limitation of that
engine itself); Sharing/Access/Approval/Workspace/Tenant Policy are recognized and
scope-matched but never yield violations, so they never reject a Result here either.

## 11. Filtering

`KnowledgeFilter.apply(results, filters)` short-circuits to `results` unchanged when no
structural filter field is set. Otherwise it resolves each Result's underlying
`KnowledgeAsset` via the injected `KnowledgeResolver` and excludes the Result when the
Asset cannot be resolved, or when any of the 13 structural fields (workspaceId,
departmentId, tenantId, classification, language, region, categoryId, tags — every
requested tag must be present, version — compared as `major.minor.patch`, templateId,
source — compared against `asset.sourceId`, assetType, lifecycleState) does not match.
Permission/Policy are explicitly excluded from `KnowledgeFilter`'s own checks — that would
duplicate `KnowledgePermissionResolver`/`KnowledgePolicyResolver`'s own job. An orphaned
Result is excluded here (safer default) whenever any structural filter is set — a
deliberate design distinction from the Policy Resolver's permissive pass-through for the
same case, since Filtering's job is "does this Result match what the caller asked for,"
not "is this Result safe to expose."

## 12. Validator

5 stages, run in fixed order by `KnowledgeRetrievalValidator`, aggregating every issue
without short-circuiting: **Query** (flags empty `searchModes`, and blank `text` with no
`keywords`), **Context** (flags blank `tenantId`/`correlationId`), **Search Mode** (flags
unknown enum values and duplicate `searchModes` entries), **Filter** (flags duplicate
`filters.tags`), **Limit** (flags `limit > 200`). Accepts optional caller-supplied
`extraStages`.

## 13. Session

`KnowledgeQuerySession` — "Supports Open, Resume, Close, Cancel, Expire, Renew" — an
in-memory `Map<token, KnowledgeQuerySessionRecord>` with a 4-state vocabulary
(`KnowledgeQuerySessionState`: Open/Closed/Cancelled/Expired — no Suspended, since the
prompt's own op list has no paired "Suspend"). `resume()` is legal from `Closed` or
`Expired` back to `Open`; `renew()` throws `RetrievalLeaseException` once the lease has
already expired. Distinct from the Retrieval Lifecycle State Machine — the two are not
automatically kept in sync by this package.

## 14. Metrics

`IKnowledgeRetrievalMetrics` / `KnowledgeRetrievalMetrics` — the exact 11-field prompt
list: Total Queries, Successful Queries, Failed Queries, Average Latency, Average Ranking
Time, Average Filter Time, Permission Reject Count, Policy Reject Count, Workspace Usage,
Tenant Usage, Search Mode Statistics.

## 15. Health

5 statuses (Healthy/Warning/Degraded/Unavailable/Unknown — `HealthStatus`).
`KnowledgeRetrievalHealth.check()` derives Registry health from whether any of the 7
buckets has an entry (`unknown` when empty, `healthy` otherwise), and Query health from
the live `failedQueries/totalQueries` ratio (`healthy` at 0, `warning` ≤ 0.2, `degraded`
≤ 0.5, `unavailable` above). Overall status is the worst of the two.

## 16. Monitoring

one `KnowledgeRetrievalDashboard` carrying all 7 named sections from the source prompt:
Search, Ranking, Latency, Workspace, Permission, Policy, Usage — plus `health`, `metrics`,
and `sampledAt`.

## 19. Technical Debt

- `KnowledgeQuerySession` and the Retrieval Lifecycle State Machine are two independent
  state ledgers over the same `KnowledgeRetrievalToken` — a caller wanting session-scoped
  retrieval history must correlate them itself.
- `KnowledgeRetriever`'s post-pipeline state transitions (`RESOLVING` →... →
  `FILTERING` → `COMPLETED`) are recorded in rapid succession after one atomic
  `KnowledgeSearchPipeline.run()` call rather than being driven stage-by-stage from
  inside the Pipeline itself — accurate lifecycle bookkeeping, but not a mechanism a
  caller can hook mid-Pipeline.
- `KnowledgePermissionResolver`'s `IResultPermissionChecker` is permissive by default;
  a production deployment must supply a real checker before this package can honor
  "Never expose unauthorized knowledge" for real tenant data.

## 20. Known Limitations

- All 12 Extension Point contracts (`contracts/`) have zero implementations — by design.
- `KnowledgeSearchStrategy`/`KnowledgeRankingEngine` ship zero registered providers; a
  caller must register at least one Search Strategy before `KnowledgeRetrieval.search()`
  can return any results.
- `knowledge.search.health.changed`/`.metrics.updated` are declared in
  `KnowledgeRetrievalEventType` but never published — no scheduled Health/Metrics-diffing
  sampler exists in this package (matching the same documented gap in
  `@aos/knowledge-indexing`'s `knowledge.index.health.changed`).
- `KnowledgePolicyResolver` inherits `KnowledgePolicyEngine`'s own documented limitation:
  only Retention/Classification/Compliance/Review Policy types can ever produce a
  violation; Sharing/Access/Approval/Workspace/Tenant Policy types are matched but never
  enforced.

## 21. Readiness Checklist for 005.7E — Enterprise Knowledge Synchronization

**Not implemented in this package** — explicitly out of scope per the source prompt. What
005.7E can build on:

- ✅ `KnowledgeResolver` already exposes `resolveAsset()`/`resolveVersionHistory()`/
  `resolveIndexEntriesByAsset()` — a Synchronization layer can read current retrieval-side
  state without querying `@aos/knowledge-engine`/`@aos/knowledge-indexing` directly.
- ✅ `KnowledgeRetrievalEvents` publishes a stable, versioned event vocabulary
  (`knowledge.search.*`) a Synchronization package can subscribe to for cache
  invalidation or downstream index refresh triggers.
- ✅ `KnowledgeRetrievalRegistry`'s `SEARCH_PROVIDER`/`RESULT_BUILDER` buckets are ready
  for a Synchronization-aware provider that revalidates or refreshes cached Search
  Results.
- ⚠️ This package has no cache layer of its own (`IKnowledgeCacheProvider` is
  interface-only, zero implementations) — Synchronization will need to either implement
  that contract or manage its own cache external to this package.
- ⚠️ No versioning/staleness signal is attached to `KnowledgeResult` beyond the `version`
  string copied from the resolved Asset at query time — Synchronization should not assume
  a `KnowledgeResult` reflects the Asset's _current_ state once the query has returned.
- ❌ Do not implement Synchronization inside `@aos/knowledge-retrieval` — this package's
  Dependency Rules and its "Enterprise Retrieval Orchestrator only" boundary must remain
  intact for 005.7E to layer cleanly on top.
