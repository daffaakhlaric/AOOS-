```

  createInstance() ──────▶│  loader/  (read-only IWorkflowDefinitionRegistry) │

                          └──────────────────┬───────────────────────┘
                                             │  WorkflowInstance (CREATED) + WorkflowContext
                                             ▼
                          ┌──────────────────────────────────────────┐
                          │  execution/WorkflowExecutionCoordinator    │
                          │  (Map<ExecutionToken, WorkflowExecution>)  │
                          └──────────────────┬───────────────────────┘
                                             │
  initialize()/start()/pause()/resume()/    │
  cancel()/expire()/complete()/fail() ──────▶│
                          ┌──────────────────────────────────────────┐
                          │  middleware/RuntimeMiddlewarePipeline      │
                          │  Validation → Permission → Tracing →       │
                          │  Metrics → Lifecycle (terminal)            │
                          └──────────────────┬───────────────────────┘

                          │  events/WorkflowRuntimeEventPublisher      │
                          │  → workflow.instance.* → @aos/event-bus    │
                          └──────────────────────────────────────────┘
```

`WorkflowRuntime` (`runtime/workflow-runtime.ts`) is the composition root and this
package's _entire_ public API — per the closing note in the source prompt ("every package
should have a small, stable public API"), no consumer of this package should ever import
from `instance/`, `state-machine/`, `middleware/`, etc. directly; `bootstrap/
workflow-runtime-system.ts`'s `WorkflowRuntimeSystem` wraps it as an `@aos/runtime-kernel`
`IModule` for a future Kernel bootstrap call (not wired into one in this Engineering Task).

## 2. Workflow Instance Lifecycle

```
create (factory)  ──▶  Created
Created  ──initialize()──▶  Ready
Ready    ──start()──▶       Running               (stamps startedAt)
Running  ──pause()──▶       Paused  ──resume()──▶  Running
Ready/Paused/Waiting ──expire()──▶ Expired         (stamps completedAt)
Created/Ready/Running/Waiting/Paused ──cancel()──▶ Cancelled  (stamps completedAt)
Running/Waiting ──complete()──▶ Completed          (stamps completedAt)
Running/Waiting ──fail()──▶ Failed                 (stamps completedAt, records reason)
Failed ──(future Node Runtime)──▶ Compensating ──▶ Compensated
```

`restart()` is declared as `IRestartable` (`lifecycle/i-lifecycle-manager.ts`) — **no
class in this package implements it**, per the source prompt's "Restart (interface
only)". Every operation above is exposed on `WorkflowRuntime` and addressed strictly by
`ExecutionToken`.

## 3. State Machine Diagram

```
CREATED ──▶ READY ──▶ RUNNING ──▶ COMPLETED
  │           │          │  │
  │           │          │  └──▶ WAITING ──▶ RUNNING
  │           │          ├──▶ PAUSED ──▶ RUNNING
  │           │          ├──▶ FAILED ──▶ COMPENSATING ──▶ COMPENSATED
  │           │          └──▶ CANCELLED
  │           ├──▶ CANCELLED
  │           └──▶ EXPIRED
  └──▶ CANCELLED
```

`WorkflowStateMachine.transition()` (`state-machine/workflow-state-machine.ts`) is the
**only** code in this package allowed to change `WorkflowInstance.status` /
`WorkflowContext.currentState`; every transition not present in `instance/
instance-state.ts`'s `INSTANCE_STATE_TRANSITIONS` throws `IllegalTransitionException`.
Every legal transition appends one `WorkflowHistoryEntry` (`sequence`, `fromState`,
`toState`, `occurredAt`, `reason?`) to `WorkflowContext.executionHistory`.

## 4. Execution Context Diagram

```
WorkflowContext
├── tenantId?, correlationId, traceId?
├── workflowVariables: Record<string, unknown>
├── environmentVariables: Record<string, unknown>
├── executionVariables: Record<string, unknown>

├── currentState: InstanceState

```

Every field the source prompt lists under "EXECUTION CONTEXT" is present. `ExecutionMode`
is carried through and published in every event's implicit context, but **never branched
on to change behavior** in this package — that interpretation belongs entirely to the
future Node Runtime (005.6C).

## 5. Snapshot Architecture

```
SnapshotManager (in-memory, Map<ExecutionToken, WorkflowSnapshot[]>)
  .capture(execution) → WorkflowSnapshot { id, instanceToken, sequence, capturedAt, instance, context }
  .list(token)   → every Snapshot captured for that Instance
  .latest(token) → throws SnapshotException if none captured yet
```

`runtime.snapshot(token)` captures one, then writes `WorkflowInstance.snapshotRef`
(`{snapshotId, sequence, capturedAt}`) back onto the live Instance and publishes
`workflow.instance.snapshot.created`. **Checkpoint** (`checkpoint/i-checkpoint.ts`) is
interface-only per the source prompt — `ICheckpoint`/`ICheckpointStore`, no implementing
class. **No persistence** anywhere in this module, exactly as specified.

## 6. Registry Integration Flow

```
WorkflowLoader (loader/workflow-loader.ts)
  .loadById(id)              → loadLatest(id)
  .loadByVersion(id, version) → IWorkflowDefinitionRegistry.get(id, version)
  .loadLatest(id)             → IWorkflowDefinitionRegistry.get(id)  [omitted version = latest]
  .loadRegisteredVersions(id) → IWorkflowDefinitionRegistry.versions(id)
  .validateCompatibility(id, from, to) → @aos/workflow-definition's CompatibilityChecker
```

Every call is **read-only** against `@aos/workflow-definition`'s
`IWorkflowDefinitionRegistry` — this package never calls `register()`/`remove()`/
`setStatus()`. Version Registry and Schema Registry are consumed transitively through
that same interface (`versions()`/`get()`), exactly as the source prompt specifies
("REGISTRY: ... Read only").

```

workflow.instance.initialized        ← initialize()
workflow.instance.started            ← start()
workflow.instance.paused             ← pause()
workflow.instance.resumed            ← resume()
workflow.instance.completed          ← complete()
```

Every event is published through the real `@aos/event-bus` `IPublisher` via

package calls a downstream Runtime directly.

```
WorkflowRuntimeMetricsCollector
├── runningWorkflows       (incremented on create, decremented on complete/fail)
├── completedWorkflows     (incremented on complete)
├── failedWorkflows        (incremented on fail)
├── averageRuntimeMs       (mean of completedAt - startedAt across completions)
```

`WorkflowRuntimeMonitor` (`monitoring/`) combines a Metrics snapshot with a

`ComponentHealth` convention) into one `sample()`, and re-exports `@aos/event-bus`'s
Tracing port (`ITracer`/`ISpan`/`createTraceContext`/`InMemoryTracer`) unchanged —
"OpenTelemetry Ready" without adding an OTel dependency.

## 9. Technical Debt

- **`PermissionMiddleware` and `WorkflowRuntimeValidator` both enforce Tenant Isolation
  independently.** `createInstance()` calls the Validator directly (defense in depth,
  since Instance creation happens before any state exists for the Middleware Pipeline to
  operate on); every subsequent lifecycle operation re-checks it via
  `PermissionMiddleware`. This is intentional layered security, not a bug, but it is
  duplicated logic a future refactor could consolidate into one shared tenant-check
  helper.
- **`WorkflowExecutionCoordinator` is in-memory only** (`Map`-backed) — no persistence
  adapter exists yet; a durable store is future work behind a new interface this package
  does not yet define (unlike `@aos/workflow-definition`'s `IWorkflowDefinitionRegistry`,
  there is no `IWorkflowExecutionStore` port here to swap an implementation into).
- **`IExecutionLease`/`IExecutionLeaseProvider` have zero implementations and zero call
  sites** — by design, per the user's explicit "belum dipakai" (not used yet) — but this
  means the interface shape is unvalidated against a real multi-node scenario; the first
  concrete `IExecutionLeaseProvider` implementation may reveal the interface needs
  adjustment (e.g. a `renew()` failure mode beyond `undefined`).
- **`ExecutionMode` is carried but never interpreted anywhere in this package** — a
  `SIMULATION`-mode Instance behaves identically to a `NORMAL`-mode one at the Runtime
  Core layer; interpreting the mode is explicitly deferred to the future Node/Execution
  Runtime (005.6C/005.6D).

## 10. Known Limitations

- No Node Runtime, Capability Runtime, Tool Runtime, Planner, Reasoner, Reflection,
  Memory Engine, Simulation Runtime, AI Gateway, Model Router, or Agent Runtime exists in
  this package — by design, per the prompt's explicit boundary.
- `WorkflowInstance.executionPointer` is set to the Start Node at creation and never
  advances anywhere else in this package — no Node execution means no Transition is ever
  actually traversed; this is the exact hook a future Node Runtime will update.
- `ICompensationHandler`/`ICompensationCoordinator` (`compensation-interface/`) and
  `IWorkflowReplay` (`replay-interface/`) are interfaces only — `runtime.replay()` throws
  `ReplayNotSupportedException` unless a caller supplies their own `IWorkflowReplay` via
  `WorkflowRuntimeConfig`; no compensation ever actually runs, even when an Instance
  reaches `COMPENSATING` (nothing in this package drives that transition either — it is
  reachable only from `FAILED`, and nothing calls it).
- `WorkflowRuntimeSystem` (the `IModule` implementation) is not wired into any real
  Kernel `buildKernel({ modules: [...] })` call in this Engineering Task — readiness-only,
  matching the precedent set by `@aos/workflow-definition`'s `WorkflowDefinitionSystem`
  and `@aos/scheduler`'s `SchedulerSystem`.
- The Runtime Middleware Pipeline's `use()` inserts new middleware _before_ the terminal
  Lifecycle stage only — there is no way to register a middleware that wraps outside the
  built-in Validation stage (e.g. an audit log that also captures rejected/invalid
  requests before Validation runs). A future revision could expose separate "pre" and
  "post" extension points if that need arises.

## 11. Readiness Checklist for ENGINEERING TASK 005.6C — Node Runtime

- [x] `WorkflowInstance` + `WorkflowExecution` give a Node Runtime a stable, versioned
      aggregate to execute against — Instance state, Execution Context, and the source
      `WorkflowDefinition` are all resolvable from one object via `runtime.getInstance(token)`.
- [x] `ExecutionToken`-based addressing means a Node Runtime never needs to scan for "the
      Instance that's currently Running" — every operation is O(1) by token.
- [x] `WorkflowResolver` already gives structural Node/Transition lookups
      (`resolveNode`, `resolveOutgoingTransitions`) a Node Runtime can build on directly
      without re-deriving them from the raw `WorkflowDefinition`.
- [x] The State Machine's `INSTANCE_STATE_TRANSITIONS` table is the authoritative
      contract a Node Runtime must respect when it starts driving `RUNNING ⇄ WAITING`
      transitions (currently unreachable through this package's own public API, since no
      Lifecycle operation exposes a raw "wait" — that becomes 005.6C's concern).
- [x] `RuntimeMiddlewarePipeline` is already extensible — a Node Runtime (or a
      Solution Pack) can register audit/billing/quota middleware via `runtime.use()`
      without this package changing.
- [x] `workflow.instance.*` events are already flowing on the real `@aos/event-bus` — a
      Node Runtime can subscribe to `workflow.instance.started`, and eventually publish
      its own `node.execution.*` namespace alongside it without any change here.
- [ ] **Not started**: any actual Node execution, Expression evaluation, Variable binding
      at runtime, or Transition traversal — `executionPointer.currentNodeId` is set once
      at creation and never advances.
- [ ] **Not started**: `WAITING` state is reachable in `INSTANCE_STATE_TRANSITIONS` but no
      Lifecycle operation in this package ever produces it — a Node Runtime driving a
      Wait Node will need its own state-transition call against `WorkflowStateMachine`
      (or this package will need a new `wait()` Lifecycle operation added in 005.6C).
- [ ] **Not started**: Compensation execution, Replay execution, and Checkpoint
      persistence — all three remain interface-only extension points a Node/Execution
      Runtime (005.6C/005.6D) is expected to implement concretely.
- [ ] **Not started**: any Agent/Tool/Capability/Planner/Reasoner integration —
      `CapabilityNode` resolution and invocation is entirely out of scope here.

**Do NOT implement Node Runtime as follow-up work here — that is 005.6C's scope.**
