# ENGINEERING TASK 005.7C — Enterprise Knowledge Indexing — Closing Report

Package: `packages/knowledge-indexing` (`@aos/knowledge-indexing`)
Source prompt archived at: `docs/PROMPT-005.7C-KNOWLEDGE-INDEXING.md`

Scope actually implemented: the vendor-neutral indexing layer that prepares searchable
indexes for future retrieval — 17 Index Types, an 8-stage Validator, a 10-stage Pipeline
(Validation → Metadata → Classification → Namespace → Policy → Permission →
Relationship → Builder → Registry → Metrics), a token/id-addressed Registry (7 buckets),
a Manager orchestrating Registry + Statistics + Scheduler, a Builder producing
`KnowledgeIndexEntry` records per Index Type, an interface-only Optimizer (Merge/Split/
Compaction/Vacuum/Rebuild), an in-memory Scheduler job ledger (Reindex/Incremental/Full/
Version/Policy/Relationship Update), a 7-event `KnowledgeIndexEvents` publisher, Metrics/
Health/Monitoring, 8 interface-only extension points, and the `KnowledgeIndexing`/
`KnowledgeIndexer` public façade (plus its `KnowledgeIndexingSystem` Kernel Module
wrapper). **No retrieval, no query answering, no RAG, no LLM calls, no vector database
implementation, and no embedding generation** was implemented, imported, or stubbed
anywhere in this package — it only creates, updates, maintains, validates, and optimizes
indexes.

`KnowledgeIndexing` (`indexing/knowledge-indexing.ts`) is the composition root and this
package's public façade — per the source prompt's Public API list (18 names:
`KnowledgeIndexing`, `KnowledgeIndexingSystem`, `KnowledgeIndexer`,
`KnowledgeIndexRegistry`, `KnowledgeIndexManager`, `KnowledgeIndexBuilder`,
`KnowledgeIndexValidator`, `KnowledgeIndexPipeline`, `KnowledgeIndexContext`,
`KnowledgeIndexFactory`, `KnowledgeIndexMetrics`, `KnowledgeIndexHealth`,
`KnowledgeIndexMonitor`, `KnowledgeIndexEvents`, `KnowledgeIndexScheduler`,
`KnowledgeIndexOptimizer`, `KnowledgeIndexStatistics`, `KnowledgeIndexResolver`). As in
`@aos/knowledge-engine`/`@aos/knowledge-runtime`'s non-"Export ONLY" packages,
`src/index.ts` also re-exports the Domain/Contracts/Errors/Validator-stage surface a
caller needs to actually build and use them.

`KnowledgeIndexer` is the narrower "verb" class that actually runs one Pipeline
invocation for one `KnowledgeAsset` and publishes the matching event;
`KnowledgeIndexing` is the "noun" façade a caller constructs, owning the Manager,
Indexer, Resolver, Optimizer, Factory, and Validator behind one entry point — mirroring
the layered composition pattern already established by
`@aos/knowledge-runtime`'s `KnowledgeRuntime` → `KnowledgeRuntimeManager` split.

## 2. Domain Model

17 Index Types (`KnowledgeIndexType`): Keyword, Metadata, Namespace, Relationship,
Policy, Permission, Template, Tag, Category, Language, Workspace, Tenant, Department,
Collection, Asset Type, Embedding Reference, Hybrid Metadata. `KnowledgeIndexEntry`
(`domain/knowledge-index-entry.ts`) is the central aggregate: `id`, `indexType`,
`assetId`, `namespace`, `tenantId`/`workspaceId`/`departmentId`, `key`, `value`
(a `Record<string, unknown>` payload shaped per Index Type), `version`
(`KnowledgeIndexVersion` — Major/Minor/Patch, bumped on rebuild), `chunkRefs` (readonly
`KnowledgeChunkReference[]` — "Store ONLY chunk references"), an optional `embeddingRef`
(`KnowledgeEmbeddingReference` — "Never generate embeddings. Only store references"),
`createdAt`/`updatedAt`.

## 3. Runtime Flow / Pipeline

`KnowledgeIndexPipeline.run({asset, indexTypes, context, relationships?})`:

1. **Validation** — runs `KnowledgeIndexValidator`'s 8 stages, throwing
   `IndexValidationException` on failure.
2. **Metadata** — normalizes `context.language`, falling back to `asset.metadata.language`
   when the caller didn't set one.
3. **Classification** — annotates `context.variables.classificationRank` via
   `@aos/knowledge-engine`'s `KNOWLEDGE_CLASSIFICATION_RANK`.
4. **Namespace** — annotates `context.variables.namespace` with the parsed
   `knowledge://` components.
5. **Policy** — delegates to an optional `IKnowledgeIndexChecker`; permissive by default.
6. **Permission** — delegates to an optional `IKnowledgeIndexChecker`; permissive by
   default.
7. **Relationship** — attaches caller-supplied `relationships` onto
   `context.variables.relationships` for the Builder's `RELATIONSHIP` case to read.
8. **Builder** — `KnowledgeIndexBuilder.build()` produces one or more
   `KnowledgeIndexEntry` records per requested Index Type (`TAG` produces one per tag;
   every other type produces exactly one, except `EMBEDDING_REFERENCE`, which throws
   `IndexBuildException` when no valid `embeddingRef` was supplied).
9. **Registry** — `KnowledgeIndexRegistry.replace()` writes every built Entry into the
   `INDEX` bucket (a rerun for the same Asset replaces rather than duplicates).
10. **Metrics** — records per-Index-Type entry counts, Tenant/Workspace Usage, and the
    total Build time.

`KnowledgeIndexer.indexAsset()` wraps one `run()` call, publishing `CREATED` (first time)
or `UPDATED` (subsequent runs) on success, `FAILED` on any thrown exception.
`reindexAsset()` removes every existing Entry for the Asset first, then re-runs and
publishes `REBUILT`. `removeAsset()` removes every Entry for an Asset and publishes
`DELETED`.

## 4. Chunk References & Embedding References

Neither is ever generated by this package. `KnowledgeChunkReference`
(`domain/knowledge-chunk-reference.ts`) is a pure pointer (`assetId`, `sequence`,
`externalRef`) — a future `IKnowledgeChunkProvider` implementation supplies the real
chunk data elsewhere; this package never chunks a document. `KnowledgeEmbeddingReference`
(`domain/knowledge-embedding-reference.ts`) matches the exact field list from the source
prompt (`embeddingId`, `provider`, `version`, `model`, `status`) — a future
`IKnowledgeEmbeddingProvider` generates the real embedding and hands back only this
reference for `KnowledgeIndexBuilder`'s `EMBEDDING_REFERENCE` case to store.

## 5. Registry

`KnowledgeIndexRegistry` (`registry/knowledge-index-registry.ts`) is one generic class
covering all 7 buckets the source prompt requires (Index/Version/Namespace/Template/
Policy/Relationship/Statistics — "Health" is derived, not stored, see §8) via a single
`Map<KnowledgeIndexRegistryBucket, Map<string, Identified>>`, mirroring
`@aos/knowledge-engine`'s `KnowledgeRegistry` pattern.

## 6. Optimizer

`KnowledgeIndexOptimizer` (`optimizer/knowledge-index-optimizer.ts`) owns **no
optimization logic itself** — "Interface only. No optimization logic." — every one of
its 5 operations (`merge`/`split`/`compact`/`vacuum`/`rebuild`) delegates to an injected
`IKnowledgeIndexOptimizer`, throwing `IndexOptimizationNotSupportedException` when none
is configured (mirroring `@aos/knowledge-runtime`'s Replay-not-configured pattern).

## 7. Scheduler

`KnowledgeIndexScheduler` (`scheduler/knowledge-index-scheduler.ts`) is an in-memory job
ledger tracking the 6 named job types (Reindex/Incremental/Full/Version Update/Policy
Update/Relationship Update) through `pending → running → completed|failed|cancelled`.
This package **never performs the actual reindex work itself** — the Scheduler only
records that work was requested and its outcome; a caller reacting to a scheduled job is
expected to invoke `KnowledgeIndexing.reindexAsset()` (or equivalent) to do the real work.

## 8. Validation

`KnowledgeIndexValidator` (`validator/knowledge-index-validator.ts`) runs 8 stages in
fixed order, aggregating every issue without short-circuiting — no duplicated validation
logic, per the source prompt: Namespace, Metadata, Relationships, Policy, Permission,
Embedding Reference, Duplicate, Consistency. Policy/Permission stages check only
structural well-formedness (a valid `Classification`, a non-blank Owner); real
enforcement is delegated to the Pipeline's own Policy/Permission stages via an injected
`IKnowledgeIndexChecker`. `ConsistencyValidator` flags an already-registered Entry whose
`namespace` disagrees with the Asset's current `namespace` — a sign the Asset moved
without a Reindex. Accepts an optional `extraStages` array.

## 9. Metrics

```
KnowledgeIndexMetrics
├── indexCount (derived: sum of entriesByType)
├── buildCount / buildFailures / rebuildCount / optimizeCount
├── averageBuildTimeMs
├── tenantUsage / workspaceUsage
└── entriesByType   (per-KnowledgeIndexType gauge)
```

## 10. Health

5 statuses (Healthy/Warning/Degraded/Unavailable/Unknown), matching the vocabulary
established by `@aos/knowledge-engine`/`@aos/knowledge-runtime`.
`KnowledgeIndexHealth.check()` derives: Registry health from whether any `INDEX` bucket
entry is registered (`unknown` if empty, else `healthy`); Build health from the live
`buildFailures / buildCount` ratio (`>0.5` unavailable, `>0.2` degraded, `>0` warning,
else healthy); overall `status` is the worst of both.

## 11. Monitoring

`KnowledgeIndexMonitor.sample()` (`monitoring/knowledge-index-monitor.ts`) combines a
Metrics snapshot with a Health report into one `KnowledgeIndexDashboard` (Index/Build/
Tenant/Workspace sections plus the full Health report and Metrics snapshot).

## 14. Technical Debt

- **The "KnowledgeIndexing vs KnowledgeIndexer" split required a judgment call.** The
  source prompt lists both names in its Public API without further description. This
  package reads `KnowledgeIndexer` as the narrower per-Asset execution unit and
  `KnowledgeIndexing` as the owning façade, mirroring the `KnowledgeRuntime` →
  `KnowledgeRuntimeManager` layering already established in `@aos/knowledge-runtime`. A
  future revision could collapse them if the distinction proves unnecessary friction.
- **The 10-stage Pipeline is a fixed sequential pipeline, not an extensible Middleware
  chain** — unlike `@aos/knowledge-runtime`'s `KnowledgeRuntimeMiddleware`, this package's
  source prompt describes the Pipeline as a fixed named sequence without mentioning a
  `.use()` extensibility point, so `KnowledgeIndexPipeline` does not expose one. A future
  revision could add one if a caller needs custom cross-cutting stages.
- **`KnowledgeIndexScheduler` never performs the reindex work it schedules** — it is
  purely a job ledger; the actual "do the reindex" step is `KnowledgeIndexing
.reindexAsset()`, which a caller must invoke itself in reaction to a scheduled job.
- **`Collection` Index keys off the namespace's `library` segment** — the source prompt
  lists "Collection Index" without defining what a Collection is on a `KnowledgeAsset`
  (there is no `collectionId` field); this package uses the parsed `knowledge://` URI's
  library segment as the closest available proxy.

## 15. Known Limitations

- **All 8 extension-point contracts have zero implementations** — by design:
  `IKnowledgeEmbeddingProvider`, `IKnowledgeChunkProvider`, `IKnowledgeVectorProvider`,
  `IKnowledgeKeywordIndexer`, `IKnowledgeMetadataIndexer`, `IKnowledgeGraphIndexer`,
  `IKnowledgeIndexOptimizer`, `IKnowledgeIndexStorage`. "Only Index Management."
- **No retrieval, no query answering, no RAG, no LLM calls, no vector database
  implementation, no embedding generation** — none implemented anywhere in this package.
- **`knowledge.index.health.changed` is declared but never published** — publishing it
  requires diffing two `KnowledgeIndexHealthReport` snapshots over time, which needs a
  scheduled sampler this package deliberately does not include, mirroring the identical,
  already-documented limitation in `@aos/knowledge-runtime` and `@aos/knowledge-engine`.
- **`KnowledgeIndexOptimizer` has zero real Merge/Split/Compaction/Vacuum/Rebuild logic**
  — by design; every operation is a pure delegate to a caller-supplied provider.
