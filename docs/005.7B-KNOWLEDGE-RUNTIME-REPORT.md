# ENGINEERING TASK 005.7B — Enterprise Knowledge Runtime — Closing Report

Package: `packages/knowledge-runtime` (`@aos/knowledge-runtime`)
Source prompt archived at: `docs/PROMPT-005.7B-KNOWLEDGE-RUNTIME.md`

Scope actually implemented: the runtime lifecycle layer that bridges `@aos/knowledge-engine`
to Workflow Runtime, Memory, Prompt Intelligence, Capability Runtime, and Agent Runtime — a
13-state strict finite-state machine, a token-addressed Registry, a read-only Loader/Resolver
pair over the Knowledge Engine, an 11-stage Validator, an 8-stage Middleware pipeline, a
Session engine (Open/Close/Suspend/Resume/Renew/Expire/Destroy), a 6-class Factory Layer, a
12-event `KnowledgeRuntimeEvents` publisher, Metrics/Health/Monitoring, 10 interface-only
extension points, and the `KnowledgeRuntime` public façade (plus its `KnowledgeRuntimeSystem`
Kernel Module wrapper). **No embedding, vector search, RAG, retrieval, chunking,
synchronization, AI, LLM, search engine, prompting, memory, or agent logic** was implemented,
imported, or stubbed anywhere in this package — it manages runtime state only.

## 2. Runtime Flow

`KnowledgeRuntime.createInstance(input)` → `KnowledgeRuntimeFactory.createExecution()`
builds a fresh `KnowledgeRuntimeInstance` + `KnowledgeRuntimeContext` in the `CREATED`
state → `KnowledgeRuntimeManager.register()` → records `runtimeCount`/`activeRuntimeCount`
→ publishes `knowledge.runtime.created`.

Every subsequent operation (`load`/`validate`/`start`/`suspend`/`resume`/`complete`/
`fail`/`cancel`/`expire`/`destroy`) runs through `runOperation(token, operation, reason?)`:

1. `KnowledgeRuntimeManager.require(token)` — token lookup, never a scan.
2. The full `KnowledgeRuntimeMiddleware` pipeline: Validation (runs `KnowledgeRuntimeValidator`, throwing `RuntimeValidationException` on failure) → Context (stamps `contextSeenAt`) → Permission (optional `IKnowledgeRuntimePermissionChecker`) → Policy (optional `IKnowledgeRuntimePolicyChecker`) → Tracing (one Span per operation via `@aos/event-bus`'s `ITracer`) → Metrics (records Tenant/Workspace Usage) → Lifecycle (the state-changing stage — dispatches to `KnowledgeRuntimeLifecycle`, writes the result back onto `context.execution`) → Logging (structured before/after/error log lines) → any custom Middleware registered via `runtime.use()`.
3. `KnowledgeRuntimeManager.update()` persists the post-transition Execution.
4. `recordStateChange()`; the matching `KnowledgeRuntimeEventType` (if any) is published with `{fromState, toState}`.

`load(token)` and `validate(token)` are two-step conveniences on the façade — `load()`
reads the `KnowledgeAsset` via `KnowledgeRuntimeLoader` (recording `loadTime`), then runs
`"load"` (→`LOADING`) followed by `"markLoaded"` (→`LOADED`); `validate()` runs
`"validate"` (→`VALIDATING`) followed by `"markReady"` (→`READY`). `resume()` similarly
runs `"resume"` (→`RESUMING`) then `"markResumed"` (→`RUNNING`). A failed `Validation`
stage publishes `knowledge.runtime.validation.failed` and records `validationFailures`
instead of the operation's normal event.

## 3. State Machine

13 states (`KnowledgeRuntimeState`): Created, Loading, Loaded, Validating, Ready, Running,
Suspended, Resuming, Completed, Failed, Cancelled, Expired, Destroyed.
`KNOWLEDGE_RUNTIME_STATE_TRANSITIONS` (`domain/knowledge-runtime-state.ts`) is the sole
authority `KnowledgeRuntimeStateMachine.transition()` consults, throwing
`IllegalRuntimeTransitionException` for any edge not listed. `DESTROYED` is the single
true terminal state (no outgoing edges); `COMPLETED`/`FAILED`/`CANCELLED`/`EXPIRED` all
transition only to `DESTROYED`. Every transition appends a `KnowledgeRuntimeHistoryEntry`
and increments `instance.statistics.transitionCount`.

## 4. Lifecycle

`KnowledgeRuntimeLifecycle` (`lifecycle/knowledge-runtime-lifecycle.ts`) exposes 13 named
operations (`load`/`markLoaded`/`validate`/`markReady`/`start`/`suspend`/`resume`/
`markResumed`/`complete`/`fail`/`cancel`/`expire`/`destroy`), each a thin wrapper around
`KnowledgeRuntimeStateMachine#transition()` that also stamps `startedAt` (on `start()`)
and `completedAt` (on `complete()`/`fail()`/`cancel()`/`expire()`). `LifecycleMiddleware`
is the only pipeline stage permitted to call these.

## 5. Registry

`KnowledgeRuntimeRegistry` (`registry/knowledge-runtime-registry.ts`) is a single
`Map<KnowledgeRuntimeToken, KnowledgeRuntimeExecution>` — "Never search runtime instances
by scanning collections. Use token lookup." `get()`/`require()`/`update()` are all O(1);
`list()` is the one enumeration operation, used only by Metrics/Health/Monitoring, never
to resolve a specific Instance.

## 6. Loader / Resolver

`KnowledgeRuntimeLoader` (`loader/knowledge-runtime-loader.ts`) reads Knowledge Assets
from the injected `KnowledgeEngine`'s `repository`/`catalog`/`registry` — strictly
read-only, never touches `KnowledgeEngine.createAsset()`/`updateAsset()`/etc.
`KnowledgeRuntimeResolver` (`resolver/knowledge-runtime-resolver.ts`) is a thin,
read-only pass-through resolving Asset/Namespace/Relationships/Dependencies/References
(via `KnowledgeRelationshipEngine`)/Policies (via `KnowledgePolicyEngine`)/Permission (via
`KnowledgePermissionEngine`)/Version History (via `KnowledgeVersionEngine`)/Templates (via
`KnowledgeTemplateEngine`) — "No retrieval. No indexing."

## 7. Session

`KnowledgeRuntimeSession` (`session/knowledge-runtime-session.ts`) implements
Open/Close/Suspend/Resume/Renew/Expire/Destroy over an in-memory
`Map<instanceToken, KnowledgeRuntimeSessionRecord>` — "No persistence." Each open Session
carries a `KnowledgeRuntimeLease` (holder/acquiredAt/expiresAt); `renew()` throws
`RuntimeLeaseException` once the Lease has already expired. Distinct from
`KnowledgeRuntimeStateMachine`: a Session tracks an access window over an Instance, not
the Instance's own execution state.

## 8. Validation

`KnowledgeRuntimeValidator` (`validator/knowledge-runtime-validator.ts`) runs 11 stages
in fixed order, aggregating every issue without short-circuiting — no duplicated
validation logic, per the source prompt: Runtime State, Context, Permission, Policy,
Lifecycle, Relationships, Namespace, Metadata, Tenant, Workspace, Execution Token. The
Permission/Policy stages only check structural well-formedness (a non-blank
`context.permission`/`context.policy` reference); actual grant/deny/violation
enforcement stays in `@aos/knowledge-engine`'s `KnowledgePermissionEngine`/
`KnowledgePolicyEngine`, reached only through the optional
`IKnowledgeRuntimePermissionChecker`/`IKnowledgeRuntimePolicyChecker` a caller injects
into `PermissionMiddleware`/`PolicyMiddleware`. Accepts an optional `extraStages` array.

## 9. Middleware

8 named stages (`Validation → Context → Permission → Policy → Tracing → Metrics →
Lifecycle → Logging`), matching the source prompt's own architecture diagram exactly,
with custom Middleware registered via `runtime.use()` appended after `Logging` — the
diagram's own trailing "Custom Middleware" position. `KnowledgeRuntimeMiddleware`
(the Public-API-named pipeline class, mirroring `@aos/workflow-integration`'s
`WorkflowIntegrationMiddleware` naming precedent) guards against a stage calling `next()`
more than once. `Permission`/`Policy` are permissive by default when no checker is
configured. `Logging` uses a package-owned `IKnowledgeRuntimeLogger` contract
(`ConsoleKnowledgeRuntimeLogger` default) rather than `@aos/logger`, since `@aos/logger`
is not in this package's allowed Dependency Rules.

## 12. Health

5 statuses (Healthy/Warning/Degraded/Unavailable/Unknown) — the same vocabulary
`@aos/knowledge-engine`'s `KnowledgeHealth` uses. `KnowledgeRuntimeHealth.check()`
derives: Registry health from whether any Instance is registered (`unknown` if empty,
else `healthy`); Validation health from the live `validationFailures / runtimeCount`
ratio; Failure Rate health from `failedRuntimeCount / runtimeCount` — both ratio-derived
components use the same `>0.5 unavailable / >0.2 degraded / >0 warning / else healthy`
thresholds established in `@aos/knowledge-engine`; overall `status` is the worst of all
three.

## 16. Technical Debt

- **The Middleware order interprets two overlapping prompt lists.** The source prompt's
  "Middleware Architecture" diagram lists 7 stages ending in `Logging` with "Custom
  Middleware" trailing after it, while its separate "Runtime Middleware" section lists 8
  names including `Context` without specifying its position. This package places
  `Context` right after `Validation` (so Permission/Policy/Tracing all observe an
  already-stamped Context) and appends caller-registered Middleware after `Logging`,
  matching the diagram's explicit trailing position literally. A future revision could
  make Context's position configurable if a concrete use case needs it earlier or later.
- **`Permission`/`Policy` Middleware are permissive by default** — matching the
  established pattern from `@aos/workflow-runtime`'s own `PermissionMiddleware` and
  `@aos/knowledge-engine`'s `KnowledgePermissionEngine`, but real enforcement requires a
  caller-supplied `IKnowledgeRuntimePermissionChecker`/`IKnowledgeRuntimePolicyChecker` —
  none is implemented in this package.
- **`knowledge.runtime.health.changed` is declared but never published** — publishing it
  requires diffing two `KnowledgeRuntimeHealthReport` snapshots over time, which needs a
  scheduled sampler this package deliberately does not include (that belongs to whichever
  future package wires `KnowledgeRuntimeMonitor` into `@aos/scheduler`), mirroring the
  identical, already-documented limitation in `@aos/workflow-integration` and
  `@aos/knowledge-engine`.
- **`executionTimeMs()`'s fallback branches (no `startedAt`/`completedAt`) are
  practically unreachable** given the legal transition table always routes through
  `start()`/`complete()` first, but are kept as defensive code rather than removed.

## 17. Known Limitations

- **All 10 extension-point contracts have zero implementations** — by design:
  `IKnowledgeRuntimeCache`, `IKnowledgeRuntimeStorage`, `IKnowledgeRuntimeCheckpoint`,
  `IKnowledgeRuntimeReplay`, `IKnowledgeRuntimeCompensation`, `IKnowledgeRuntimeObserver`,
  `IKnowledgeRuntimeHook`, `IKnowledgeRuntimeTracer` (Tracing Middleware uses
  `@aos/event-bus`'s `ITracer` by default instead), `IKnowledgeRuntimeScheduler`,
  `IKnowledgeRuntimeLeaseProvider` (`KnowledgeRuntimeSession` manages Leases purely
  in-memory instead). "This package is ONLY responsible for runtime lifecycle."
- **No embedding, vector search, RAG, retrieval, chunking, synchronization, AI, LLM,
  prompting, memory, or agent logic** — none implemented anywhere in this package.
- **`knowledge.runtime.health.changed` is declared but never published** — see Technical
  Debt.
- **`IKnowledgeRuntimeObserver`/`IKnowledgeRuntimeHook` are not wired into the Middleware
  pipeline** — declared as extension points, but no built-in Middleware stage invokes
  them; a future revision would add a dedicated stage (or extend `LoggingMiddleware`) to
  actually call registered Observers/Hooks.
