# ENGINEERING TASK 005.7A — Enterprise Knowledge Engine — Closing Report

Package: `packages/knowledge-engine` (`@aos/knowledge-engine`)
Source prompt archived at: `docs/PROMPT-005.7A-KNOWLEDGE-ENGINE.md`

Scope actually implemented: the canonical Knowledge Domain every future AOS module
(Workflow, Memory, Agent, Prompt, Capability, Connector, AI Gateway, Experience Layer,
Marketplace) will consume knowledge through — 30+ named domain aggregates, 46 Knowledge
Asset Types, a hierarchical Knowledge Namespace, a 15-type Relationship Engine, a
12-state Lifecycle, an in-memory Version Engine (bump/compare/diff/history/rollback), a
10-type Policy Engine, a scope-aware Permission Engine, a 10-bucket Registry, a
Repository/Catalog/Resolver trio, a 7-sub-factory `KnowledgeFactory`, a 14-stage
`KnowledgeValidator`, 14 interface-only extension points, an 11-event `KnowledgeEvents`
publisher, Metrics/Health/Monitoring, and the `KnowledgeEngine` public façade (plus its
`KnowledgeSystem` Kernel Module wrapper). **No embedding, vector search, RAG, chunking,
retrieval, synchronization, LLM, memory, prompting, AI reasoning, workflow execution, or
agent logic** was implemented, imported, or stubbed anywhere in this package — every one
of those concerns is represented only as an interface-only contract in `contracts/`.

## 3. Knowledge Namespace

`namespace/knowledge-namespace.ts` implements hierarchical `knowledge://tenant/workspace/
library/document` URIs: `buildKnowledgeNamespaceUri()` composes one from parts,
`parseKnowledgeNamespace()` parses one back into `{ tenantId, workspaceId, libraryId,
documentId }`, throwing `InvalidNamespaceException` for the wrong scheme or an
incorrect segment count. `isValidKnowledgeNamespace()` wraps the parser as a boolean
check. `KnowledgeRepository` indexes every saved `KnowledgeAsset` by both `id` and its
parsed namespace, so `getByNamespace()` is an O(1) lookup.

## 4. Lifecycle

12 states (`KnowledgeLifecycleState`): Draft, Imported, Pending Review, Approved,
Published, Indexed, Deprecated, Archived, Disabled, Deleted, Expired, Versioned.
`KNOWLEDGE_LIFECYCLE_TRANSITIONS` (`domain/knowledge-lifecycle-state.ts`) declares the
legal from→to edges; `KnowledgeLifecycle.canTransition()`/`transition()`
(`lifecycle/knowledge-lifecycle.ts`) enforce them, throwing
`IllegalLifecycleTransitionException` on an illegal request. Only `DELETED` is terminal
(`KNOWLEDGE_TERMINAL_LIFECYCLE_STATES`). `KnowledgeEngine.archiveAsset()` is the one
built-in transition helper on the façade; any other transition is reached via
`engine.lifecycle.transition()` directly.

## 5. Relationship Engine

15 relationship types (`KnowledgeRelationshipType`): Parent, Child, Reference,
Duplicate, Related, Depends On, Uses, Implements, Generated From, Version Of, Derived
From, Required By, Consumed By, Belongs To, Linked To. `KNOWLEDGE_RELATIONSHIP_INVERSE`
(`domain/knowledge-relationship-type.ts`) maps each type to its structural inverse (e.g.
`PARENT` ↔ `CHILD`, `DEPENDS_ON` ↔ `REQUIRED_BY`). `KnowledgeRelationshipEngine.add()`
registers the given edge **and** its inverse into the Registry's `RELATIONSHIP` bucket in
one call, indexing both directions into private `outgoingByAsset`/`incomingByAsset` maps
so `outgoing()`/`incoming()`/`neighbors()` are all O(1) per Asset.

## 6. Policy Engine

10 policy types (`KnowledgePolicyType`): Retention, Publishing, Classification, Access,
Sharing, Compliance, Validation, Review, Approval, Synchronization.
`KnowledgePolicyEngine` (`policy/knowledge-policy-engine.ts`) is **not** a generic
expression-language engine — `evaluate()` dispatches to real, testable structural logic
for exactly the 4 types whose rule semantics are unambiguous from the prompt's own
vocabulary:

- **Retention** — `rule.maxAgeDays` vs. `Asset.metadata.created`.
- **Classification** — `rule.maxClassification` vs. `Asset.classification`, compared via
  `KNOWLEDGE_CLASSIFICATION_RANK`.
- **Compliance** — `rule.requiredTags` vs. `Asset.tags`.
- **Review** — `rule.maxDaysSinceReview` vs. `Asset.metadata.reviewed`.

The remaining 6 (Publishing/Access/Sharing/Validation/Approval/Synchronization) are
recognized and scope-matched (`applicablePolicies()` still returns them) but yield no
violations — enforcement for those is intentionally delegated elsewhere
(Access/Sharing → `KnowledgePermissionEngine`, Validation → `KnowledgeValidator`,
Approval → the future `IKnowledgeApprover` contract, Synchronization → the future
`IKnowledgeSynchronizer` contract). See Known Limitations.

## 7. Permission Engine

Permission dimensions per the source prompt: Role Based, Policy Based, Department,
Workspace, Solution Pack, Tenant, Organization, Environment — all expressed through
`KnowledgePermission.scope` (a `KnowledgeScope`) plus an optional `environment` field.
`KnowledgePermissionEngine.check(context, asset, action)`:

1. Filters registered Permissions to those `applicable` to `(asset.scope, action)` via
   `scopeContains()`, **and** whose `environment` (if set) matches `context.environment`.
2. If `applicable.length === 0` (nothing governs this action/scope at all) → **permissive
   default: `true`**.
3. Otherwise, filters `applicable` to those `held` by the caller (matching
   `context.userId`/roles). A held `deny` always wins over a held `allow`. If the action
   IS governed but the caller holds none of the applicable Permissions → `false`.

`KnowledgePermission` is deliberately **not** one of the 10 `KnowledgeRegistryBucket`
values (the source prompt's Registry list omits "Permissions"), so
`KnowledgePermissionEngine` owns its own private `Map<string, KnowledgePermission>`
rather than being forced through `KnowledgeRegistry`.

## 8. Registry

`KnowledgeRegistry` (`registry/knowledge-registry.ts`) is one generic class satisfying
the prompt's "Registry for Schemas/Templates/Categories/Policies/Providers/Namespaces/
Relationships/Libraries/Collections/Versions" requirement — a single
`Map<KnowledgeRegistryBucket, Map<string, Identified>>` internally, with
`register()`/`replace()`/`get()`/`require()`/`remove()`/`list()`/`count()` all
parameterized by the 10-value `KnowledgeRegistryBucket` enum, rather than 10 separate
classes.

## 9. Validation

`KnowledgeValidator` (`validator/knowledge-validator.ts`) runs 14 stages in fixed order,
aggregating every issue without short-circuiting — no duplicated validation logic, per
the source prompt: Schema, Metadata, Version, Relationship, Namespace, Policy,
Permission, Classification, Language, Ownership, Tenant, Workspace, Collection,
Template. Each stage is its own `IKnowledgeValidatorStage` implementation
(`validator/*-validator.ts`); `KnowledgeValidator` accepts an optional `extraStages`
array for caller-supplied additions without modifying this package.
`KnowledgeEngine.assertValid()` (private) runs this validator on every
`createAsset()`/`updateAsset()` call, publishing `KnowledgeEventType.VALIDATION_FAILED`
and throwing `KnowledgeValidationException` (aggregating every issue into one message) on
failure.

## 10. Versioning

Semantic Version (Major/Minor/Patch), History, Rollback, Compare, Diff are **implemented
with real in-memory logic** (`version/knowledge-version-engine.ts`) —
`bumpMajor()`/`bumpMinor()`/`bumpPatch()`, `compare()` (-1/0/1), `snapshot()` (records
into the Registry's `VERSION` bucket and a private `historyByAsset` map), `history()`,
`rollback()` (throws `VersionConflictException` for an unknown label), `diff()` (shallow
field-by-field comparison). This reading of "No storage implementation. Only contracts."
follows the "Persistence: None" convention already established in every prior AOS
package — in-memory logic, no durable backend — not "leave Version logic unimplemented."
`Branch`/`Merge` from the prompt's vocabulary were deliberately **not** implemented (no
`branch()`/`merge()` methods exist); see Known Limitations.

## 12. Health

5 statuses per the source prompt (`Healthy`/`Warning`/`Degraded`/`Unavailable`/`Unknown`)
— a different, wider vocabulary than `@aos/workflow-integration`'s 4-value Health,
intentionally not unified since the two prompts specify different sets.
`KnowledgeHealth.check()` derives: Repository health from `count() === 0` → `unknown`,
else `healthy`; Registry health from summed bucket counts (same rule); Validation health
from the live `validationErrors / knowledgeCount` ratio (`> 0.5` → `unavailable`, `> 0.2`
→ `degraded`, `> 0` → `warning`, else `healthy`); overall `status` is the worst of all
three via a `STATUS_RANK` table that ranks `unknown` as the worst outcome.

## 15. Technical Debt

- **The 10-Registry-bucket / Permission-not-a-bucket mismatch required a judgment call.**
  Giving `KnowledgePermissionEngine` its own private store rather than adding an 11th
  Registry bucket is a reasonable reading of the source prompt's own Registry list, which
  omits Permissions — but a future revision could unify it into the Registry if
  Permission lookups need the same bucket-generic tooling (e.g. `list()` iteration) the
  other 10 buckets get for free.
- **`KnowledgePolicyEngine.evaluate()` only understands 4 of the 10 policy types'
  `rule` fields.** The remaining 6 are recognized and scope-matched but always evaluate
  to "no violations" — a real, bounded, intentional design decision (see Section 6), not
  a silent gap, but a future revision extending Access/Sharing/Approval/Synchronization
  rule semantics directly into this engine (rather than delegating) is possible.
- **`knowledge.health.changed` is declared but never published** — publishing it requires
  diffing two `KnowledgeHealthReport` snapshots over time, which needs a scheduled
  sampler this package deliberately does not include (that belongs to whichever future
  package wires `KnowledgeMonitor` into `@aos/scheduler`), mirroring the identical,
  already-documented limitation in `@aos/workflow-integration`.

## 16. Known Limitations

- **Every one of the 14 extension-point contracts has zero implementations** — by design:
  `IKnowledgeIndexer`, `IKnowledgeRetriever`, `IKnowledgeEmbeddingProvider`,
  `IKnowledgeChunker`, `IKnowledgeVectorStore`, `IKnowledgeSynchronizer`,
  `IKnowledgeGenerator`, `IKnowledgeTranslator`, `IKnowledgeReviewer`,
  `IKnowledgeApprover`, `IKnowledgeRecommendation`, `IKnowledgeGraph`,
  `IKnowledgeAnalytics`, `IKnowledgeQualityEngine`. This package "MUST NOT implement:
  Embedding, Vector Search, RAG, Chunking, Retrieval, Synchronization, LLM ... AI
  Reasoning."
- **`branch()`/`merge()` are not implemented on `KnowledgeVersionEngine`** — the source
  prompt's Versioning vocabulary names Branch/Merge alongside History/Rollback/Compare/
  Snapshot/Diff, but "No storage implementation. Only contracts." for a distributed
  branch/merge model implies a design this package's flat, single-history-per-Asset
  `historyByAsset` map does not attempt; a future Knowledge Runtime revision would need
  its own branch-graph data structure.
- **`KnowledgePolicyEngine` evaluates only Retention/Classification/Compliance/Review
  rule fields** — see Technical Debt.
- **`knowledge.health.changed` is declared but never published** — see Technical Debt.
