Package: `packages/node-runtime` (`@aos/node-runtime`)
Source prompt archived at: `docs/PROMPT-005.6C-ENTERPRISE-NODE-RUNTIME.md`

Scope actually implemented: Node validation, Node Instance creation (from Workflow
Definition / Registry / Blueprint), Node lifecycle management, and Node execution
_interfaces_ (never execution) — for all 24 "Flow Node" types plus 12 AI-native contract

## 1. Runtime Architecture

```
createFromDefinition()/createFromRegistry()/createFromBlueprint()
                    │
                    ▼
        ┌───────────────────────────┐
        │  factory/  (NodeFactory)   │──▶ resolver/ (NodeResolver) ──▶ registry/ (NodeRegistry,
        │                            │                                 wraps @aos/workflow-definition's
        └─────────────┬─────────────┘                                 SchemaRegistry — no duplication)
                       │  NodeInstance (CREATED) + NodeContext
                       ▼
        ┌───────────────────────────┐
        │  validator/ValidationPipeline │  (Schema/Configuration/Compatibility/
        └─────────────┬─────────────┘   Input-Output/Dependency/Version)
                       │
        ┌───────────────────────────┐
        │  runtime/NodeExecutionCoordinator │ (internal Map<id, NodeExecution>)
        └─────────────┬─────────────┘
                       │
  initialize()/validate()/prepare()/start()/pause()/resume()/complete()/fail()/cancel()/timeout()
                       ▼
        ┌───────────────────────────┐
        │  middleware/NodeMiddlewarePipeline │
        │  Validation → Permission → Tracing → Metrics → Logging → Lifecycle (terminal) │
        └─────────────┬─────────────┘
                       ▼
        ┌───────────────────────────┐
        │  lifecycle/NodeStateMachine │ (NODE_STATE_TRANSITIONS enforced)
        └─────────────┬─────────────┘
                       ▼
        ┌───────────────────────────┐
        │  events/NodeRuntimeEventPublisher │ → node.* → @aos/event-bus
        └───────────────────────────┘
```

`NodeRuntime` (`runtime/node-runtime.ts`) is this package's **entire public API** — per
the prompt's explicit "PUBLIC API: Expose ONLY: NodeRuntime. Everything else internal."
`src/index.ts` exports `NodeRuntime`, its Kernel Module wrapper `NodeRuntimeSystem`, and
only the data-contract surface (types/interfaces/enums/errors) required to actually call
`NodeRuntime`'s methods and interpret their results — every concrete internal
implementation class (`NodeRegistry`, `NodeResolver`, `NodeFactory`, the
Validator/Lifecycle/Middleware/Metrics/Health/Monitoring/Events concrete classes, the
`NodeExecutionCoordinator`) stays unexported. This tension — and why it's an unavoidable
minimum rather than a loophole — is documented directly in `src/index.ts`'s own comment.

## 2. Node Lifecycle

```
create (factory)      ──▶  Created
Created  ──initialize()──▶  Ready
(any)    ──validate()──▶    (no transition — runs ValidationPipeline, throws on failure)
(any)    ──prepare()──▶     (no transition — pass-through extension hook)
Ready    ──start()──▶       Running                (stamps startedAt)
Running  ──pause()──▶       Paused  ──resume()──▶   Running
Ready/Running/Waiting/Paused ──timeout()──▶ TimedOut   (stamps completedAt)
Created/Ready/Running/Waiting/Paused ──cancel()──▶ Cancelled (stamps completedAt)
Running/Waiting ──complete()──▶ Completed            (stamps completedAt)
Running/Waiting ──fail()──▶ Failed                   (stamps completedAt, records reason)
Failed ──(future Execution Engine)──▶ Compensated
```

`compensate()` is declared as `INodeCompensatable` (`lifecycle/i-node-lifecycle-manager.ts`)
— **no class in this package implements it**, per the source prompt's "Compensate
(interface only)".

## 3. Node State Machine Diagram

```
CREATED ──▶ READY ──▶ RUNNING ──▶ COMPLETED
  │           │          │  │
  │           │          │  └──▶ WAITING ──▶ RUNNING
  │           │          ├──▶ PAUSED ──▶ RUNNING
  │           │          ├──▶ FAILED ──▶ COMPENSATED
  │           │          ├──▶ CANCELLED
  │           │          └──▶ TIMED_OUT
  │           ├──▶ SKIPPED
  │           ├──▶ CANCELLED
  │           └──▶ TIMED_OUT
  └──▶ CANCELLED
```

`NodeStateMachine.transition()` is the **only** code in this package allowed to change
`NodeInstance.status`; every transition not present in `contracts/node-state.ts`'s
`NODE_STATE_TRANSITIONS` throws `IllegalNodeTransitionException`. Every legal transition
appends one `NodeHistoryEntry` to the `NodeExecution.history` array (kept at the aggregate
level rather than inside `NodeContext`, since the source prompt's "NODE CONTEXT" field
list excludes History).

## 4. Factory Flow

```
NodeFactory
  .createFromDefinition({ workflowInstanceId, definition, nodeId })
      → NodeResolver.resolveDefinitionNode() → mapDefinitionNodeType() (13 WDL Node Types
        → 35 Node Runtime Types; Task/SubWorkflow map to Custom) → deriveConfigFromDefinitionNode()
        (best-effort field copy for Capability/Delay/Human; Condition/Loop/Wait's structured
        Expression has no string equivalent this package's manifests expect — a documented
        limitation) → dependsOn derived from incoming Transitions → createNodeInstance()
  .createFromRegistry({ workflowInstanceId, nodeId, type, config? })
      → NodeRegistry.has(type) check → createNodeInstance()
  .createFromBlueprint({ workflowInstanceId, blueprint })
      → NodeRegistry.has(type) check → createNodeInstance()
```

All three throw `NodeFactoryException` when the target Node Type is not registered.
`NodeRuntime` then resolves the full `NodeManifest`, assembles the `NodeContext`, runs the
`ValidationPipeline` once (throwing `NodeValidationException` on failure), registers the
`NodeExecution`, records a `nodeCount` metric, and publishes `node.created`.

## 5. Registry Integration

```
NodeRegistry (registry/node-registry.ts)
  constructor(manifests = ALL_NODE_MANIFESTS)
    for each manifest: manifestsByType.set(type, manifest)
                       if manifest.configSchema: schemaRegistry.register(type, configSchema)
  .get(type)          → NodeManifest | undefined
  .has(type)          → boolean
  .list()             → readonly NodeManifest[]
  .getConfigSchema(type) → ZodTypeAny | undefined  (delegates to schemaRegistry.get())
```

"Integrate with existing Registry. Read-only. No duplication." is satisfied by reusing
`@aos/workflow-definition`'s `SchemaRegistry` class (built in 005.6A explicitly as "the
extension point a future custom Node Type ... would register its schema into") for
`configSchema` storage, rather than inventing a second Map-based registry mechanism. After
construction, `NodeRegistry` is read-only — nothing in this package ever calls a mutating
method on it again.

## 6. Middleware Flow

```
NodeMiddlewarePipeline: Validation → Permission → Tracing → Metrics → Logging → Lifecycle (terminal)
```

- **Validation** — runs the `ValidationPipeline` again (defense in depth; `createFrom*()`
  already validated once at creation), throws `NodeValidationException` on failure.
- **Permission** — defers to an optional `INodePermissionChecker`; permissive by default
  with none configured.
- **Tracing** — one Span per operation via `@aos/event-bus`'s `ITracer`
  (`createTraceContext`/`InMemoryTracer` by default) — "OpenTelemetry Ready".
- **Metrics** — records Execution Latency per operation.
- **Logging** — structured before/after/error log lines via `@aos/logger`'s Pino-based
  `Logger` (new in this Engineering Task — 005.6B's pipeline had no Logging stage).
- **Lifecycle** (terminal) — invokes the matching `NodeLifecycleManager` method and writes
  the result back onto `context.execution`.

`runtime.use(middleware)` inserts a caller-supplied `INodeMiddleware` before the terminal
Lifecycle stage, in call order — "Allow runtime.use()".

## 7. Event Flow

```
node.created         ← createFromDefinition()/createFromRegistry()/createFromBlueprint()
node.initialized      ← initialize()
node.started          ← start()
node.completed        ← complete()
node.failed           ← fail()
node.cancelled        ← cancel()
node.timeout          ← timeout()
node.state.changed    ← any operation whose NodeState actually changed
```

`validate()`/`prepare()`/`pause()`/`resume()` have no dedicated event type (only 8 are
specified); `pause()`/`resume()` still publish `node.state.changed` since they do change
state, while `validate()`/`prepare()` publish nothing (no state change occurs). Every
event is published through the real `@aos/event-bus` `IPublisher` via
`NodeRuntimeEventPublisher`.

## 8. Metrics

```
NodeRuntimeMetricsCollector
├── nodeCount               (incremented on every createFrom*())
├── nodeSuccessCount        (incremented on complete())
├── nodeFailureCount        (incremented on fail())
├── averageNodeRuntimeMs    (mean of completedAt - startedAt across successes)
├── countByType             (a live counter per NodeType)
└── averageExecutionLatencyMs (per-operation mean, recorded by MetricsMiddleware)
```

`NodeRuntimeMonitor` combines a Metrics snapshot with a `NodeRuntimeHealth` report
(Runtime/Registry/Factory/Validator/Resolver Health, mirroring the `ComponentHealth`
convention from `@aos/scheduler`/`@aos/workflow-runtime`) into one `sample()`, and
re-exports `@aos/event-bus`'s Tracing port unchanged.

## 9. Known Limitations

- No Workflow Execution Engine, Capability Runtime, Tool Runtime, Connector Runtime,
  Planner, Reasoner, Reflection, Memory Engine, Knowledge Engine, AI Gateway, Agent
  Runtime, Model Router, or Simulation Runtime exists in this package — by design, per the
  prompt's explicit boundary.
- `deriveConfigFromDefinitionNode()` cannot populate `config` for Condition/Loop/Wait
  Nodes created via `createFromDefinition()` — `@aos/workflow-definition`'s `Expression`
  objects have no string representation this package's built-in manifests expect; only
  Capability, Delay, and Human Nodes get a real field mapping today.
- `NodeState.WAITING` is reachable in `NODE_STATE_TRANSITIONS` but no Lifecycle operation
  in this package ever produces it — a future Execution Engine driving a Wait Node will
  need its own `NodeStateMachine` call (or a `wait()` operation added in 005.6D).
- `INodeExecutor`/`IAINodeExecutor`/`IKnowledgeProvider`/`IMemoryProvider` (and every other
  `contracts/i-*.ts` interface) have zero implementations — by design, "Create ONLY
  interfaces."
- The 12 AI-native Node manifests (`contracts/ai-native/`) validate shape only — no
  planning, reasoning, reflection, critique, debate, voting, consensus, or simulation
  logic exists; a `PromptNode`'s `template` is never rendered, a `KnowledgeSearchNode`'s
  `query` never searches anything.

## 10. Technical Debt

- **"Expose ONLY NodeRuntime" required a judgment call.** A strictly literal reading would
  export nothing else, but TypeScript consumers need types for `NodeRuntime`'s method
  parameters/return values, error classes to catch, the event enum to subscribe on, and
  the Middleware interface to write a custom stage for `.use()`. `src/index.ts` documents
  this tension inline; a future revision could split the package into a `@aos/node-runtime`
  (class only) + `@aos/node-runtime-contracts` (types) pair if a stricter boundary becomes
  load-bearing.
- **`NodeInstance.dependsOn` self-reference is the only Dependency check implemented.**
  Multi-node dependency-cycle detection is intentionally left to
  `@aos/workflow-definition`'s own `CycleValidator` — duplicating it here would violate
  "No duplication."
- **`PermissionMiddleware` has no built-in Tenant Isolation check** (unlike
  `@aos/workflow-runtime`'s equivalent) — `NodeContext.tenantId` exists, but no
  Node-level "owning tenant" concept exists on `NodeManifest`/`NodeInstance` to compare it
  against, so the check would be vacuous. Left as a pure `INodePermissionChecker`
  extension point instead.
